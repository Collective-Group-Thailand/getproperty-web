# CLAUDE.md — getproperty-web

**getproperty — บิลทำเอง เก็บเงินเอง ถูกกฎหมาย** · operated by Collective Group (Thailand) · Collective Group's Building Operations platform (D-150; no legacy; `getpack-web` is a conventions reference only, D-003)
This repository is the **Next.js 16 application for operators and the platform**. It serves three zones from one codebase and one deployment:
- **owner zone** (`OWNER_HOST`, default host, `[locale]`) — the operator's console for a **tenant** (the SaaS customer organisation, D-151: apartment first; condo juristic, PM company and landlord portfolio views later): morning dashboard, buildings & units, parties & leases & deposits, billing cycles & invoices, payments & arrears, meters & loss, service requests, settings, subscription
- **staff zone** (`STAFF_HOST`) — mobile-first PWA for building staff (caretakers / in-house technicians / installers): reading rounds with camera + OCR, inspections, device provisioning, work orders, parcels
- **admin zone** (`ADMIN_HOST`) — platform back-office for Collective Group staff: tenants & subscriptions, tariffs, device fleet & OTA, support grants, DSR, audit

**Not here**: the resident-facing LINE Mini App (LIFF) — bills/pay, service requests, lease & e-sign, usage, announcements, parcels, profile, and in R2 the technicians' "my work orders" — is the separate repository **`getproperty-liff`** (D-154). People who live in units are **residents** (parties with an `occupancy`), never "tenants"; "tenant" always means the SaaS customer organisation (D-151).

The backend is a separate repository (`getproperty-api`, NestJS). This app never talks to a database and never computes money, tariffs, billing dates or compliance — it renders what the API returns.

## Hard rules
- API types come only from `src/lib/api/schema.d.ts` generated by `pnpm gen:api` from the backend contract. Never hand-write response types. If an endpoint you need does not exist, write it into `docs/contract-requests.md` (method, path, purpose, fields) and use an MSW mock marked `// CONTRACT-REQUEST` — never invent it silently.
- Tokens live only in httpOnly cookies set by this app's server; browser code calls the zone BFF (`/bff/*`), server code calls `API_INTERNAL_URL`. No tokens in localStorage or JS-readable cookies. The current tenant is the `__Host-gp_tenant` cookie, sent upstream as `X-Tenant-Id`.
- Zone isolation: owner code must not import `src/features/staff|admin/**` and so on (ESLint `getproperty/zone-boundaries` enforces it, and refuses any `tenant`/`resident` zone segment — the resident app is `getproperty-liff`). Shared code goes to `src/ui`, `src/features/shared`, `src/lib`, `src/domain`, `src/i18n`.
- `src/ui` is the source the resident app copies from until `collective-shared` exists (D-155): a change to a token or a component used there is noted in `docs/PROGRESS.md` so `getproperty-liff` can re-sync (`pnpm shared:check` there).
- UI primitives come from `src/ui` only; extend `src/ui` instead of styling locally. All copy through `src/i18n` (th default, en). Status labels/tones/icons only from `src/domain/status`.
- Domain words follow D-151 in code, routes and English copy: tenant (SaaS customer), property → building → floor → unit, party, occupancy, lease, invoice / invoice_line, payment, receipt, rate_plan, billing_cycle, asset_item, meter_assignment, service_request, work_order. Thai copy may keep the everyday words (ห้อง, ผู้เช่า, บิล).
- Money is a decimal string from the API; format with `formatTHB`, never do arithmetic on it. Meter quantities are decimal strings; format with `formatUnits`. Dates from the API are rendered in `Asia/Bangkok` (Buddhist era for operators and residents, ISO in exports).
- Compliance refusals from the API (`compliance.*` with `legalRef`) are shown with their legal reference and never worked around in the UI (no client-side "override").
- Values that decisions mark as configurable are read from the API (settings), never hard-coded in the UI.
- Never copy third-party designs, templates, text or assets (competitor apps included). Brand = getproperty tokens.
- Plan Mode first for each deliverable; wait for approval. Small vertical slices, Conventional Commits, green CI per slice. When ambiguous: record the assumption in `docs/PROGRESS.md` and take the most conservative option.
